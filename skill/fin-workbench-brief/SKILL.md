# 财报分析简报解读

## 这个技能的前提

`fin-workbench` 是一个本地财报标注工作台。它的设计是把两件事彻底分开：

```
数字与判定  ← 代码算，可复现，同一份数据永远同一结论
解释与联想  ← 你（agent）负责，但无权改判定
```

所以你的第一动作不是分析，是**取简报**：

```bash
cd <fin-workbench 仓库根>
.venv/bin/fw-brief <6位代码> --markdown     # 给人看的版本
.venv/bin/fw-brief <6位代码>                # 结构化 JSON，字段更全
```

简报里带一个 `constraints` 数组和 `authority` 段。那不是说明文档，**是随数据一起传给你的行为契约**。

若命令报错说库是空的，说明该标的没取数，让用户先跑 `python -m fw.fetch <代码>`（一家约 25 秒）。**不要自己去 akshare 拉数然后自己算判定**——那等于绕开了整套可复现的裁决体系，给出一个无法复核的结论。

## 你必须遵守的六条

1. **不能推翻判定。** `verdict`、`risk.score`、`fscore` 都是确定性计算结果。你觉得某条规则阈值不合理时，**写成异议**并给出依据，让用户去改 `rules/pailei.md`——绝不自行动口修正结论。
2. **引用阈值必须带 rule 与 origin。** `pailei.md` 来源的是**用户规则**，优先级高；标 `教材参考值` 的只用于补充视角。二者混为一谈是这类工具最容易出的错：用户定的阈值被通用教科书结论悄悄覆盖。
3. **覆盖率低就不许比较。** `coverage < 0.85` 时必须在结论里声明覆盖不足。缺数据不等于中等质量，也不等于合格。
4. **`veto` 非空时风险分已作废。** 这时不要说「虽然被否决但分数还行」，直接讲否决项。被排除的标的与健康的标的不共用一把尺子。
5. **拒绝仓位、买卖点、目标价、涨跌预测。** 这是工具的定位，不是你的保守倾向。用户索要时说明理由，不要含糊答应。
6. **落到具体条目。** 谈原始披露就引 `source_pdf` 的链接或 `risk_announcements` 里的具体某一条某一日，不要只说「年报里有写」。

## 值得主动指出的一件事

简报里 `风险分` 和 `F-Score` 会打架，而且**打架通常最有信息量**。

F-Score 量的是九项同比变化的动量（改善/恶化），风险分量的是当前水平的质地。所以一家薄毛利、高杠杆、正在边际改善的公司会 F-Score 很高而风险分很低——这不是数据矛盾，是「在变好」和「现在好」两件事。

实测中这类分歧真实存在：某标的 F-Score 8/9 但毛利率 3.3%、权益乘数 7.9、两项规则警示；另一标的 F-Score 2/9 却是因为当期亏损触发一票否决。**遇到分歧别挑一个信，把两个口径同时摆出来并解释差在哪。**

## 输出建议的顺序

1. **一句话结论**：过没过排雷、主要短板在哪一维
2. **否决或警示项**（如果有）：引 rule 编号与理由
3. **杜邦分量与归因**：解释 ROE 是靠利润率、周转还是杠杆撑起来的，以及同比变动里哪个因子主导
4. **现金流与利润的背离**：`ocf_to_profit` 与其逐年趋势，这是 A 股最出问题的地方
5. **异议**（如有）：你认为某条规则阈值对该行业不适用——说明理由，交回用户决定
6. **下一步**：应该翻哪份公告的哪一科（用 `source_pdf` 与 `drill` 字段）

别把十二个指标逐个念一遍。简报里都有，复述没有价值；**你的增值在于把它们连成一个判断，并说清这个判断的薄弱处在哪。**

## 数据源与已知边界

这些限制会影响你的结论强度，涉及时要提：

- **金融业报表结构不同**：银行券商没有营业成本与流动资产负债概念，毛利率、周转率、流动比率是 N/A。这不是缺陷，是行业性质。别把它们当"数据缺失"来抱怨，也别硬凑。
- **同业分组来自 `watchlist.csv` 的 `group` 列**，是用户手工声明的，不是行业分类接口的结果（东财 push2 系行业接口从其网络不可达）。组内均值只是"这几只的均值"，不能当行业基准。
- **公告时间多为日级精度**（巨潮对多数公告只给日期，北京时间零点），所以"这条公告在股价波动前还是后"经常无法判定。简报里的 `ts_precision` 会标出来，别假装知道顺序。
- **F-Score 第 7 条用的是期末注册股本**，akshare 无加权口径。判断"有没有增发"够用，反推每股指标不行。

## 与姊妹项目的接缝

`vest`（题材归因管线）的研究卡里有 `followup_queue`，每项带 `question` 字段——那是归因环节**留下来的未答问题**。当用户从"某板块为什么涨"问到"那这只股票本身值不值得研究"时，那个 `question` 就是本轮该回答的目标，比你自己另起一个问题更贴近上下文。

`fin-workbench` 的输入队列会自动并上这些标的（靠 `VEST_DB_PATH` 只读挂载 vest 的 DuckDB）。看到某只标的来源含 `vest:` 前缀时，说明它是被异动归因筛出来的，回答要对着那条 question 去。

## 仓库定位

本技能随 fin-workbench 仓库分发，位于其 `skill/fin-workbench-brief/`。仓库路径不固定，**不要猜绝对路径**：用 `command -v fw-brief` 或从当前工作目录/其父级找带 `src/fw/brief.py` 的项目根；找不到就问用户仓库在哪，别拿一个硬编码路径反复试。
